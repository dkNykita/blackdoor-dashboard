BUG REPORT: Object literals cannot span multiple lines (parser limitation, undocumented)

Current behavior:
Writing an object literal across multiple lines (one key per line, a common, readable style) fails to parse with "Expected property name in object literal" - even in a minimal, syntactically valid case (2 keys, no comments):

    var small = {
        "a": 1,
        "b": 2
    }

The exact same content written on a single line works fine:

    var small = {"a": 1, "b": 2}

Expected behavior:
Every other multi-line construct in the language (if/while/for bodies, function calls split across lines) works fine. Object literals should behave consistently - either support multi-line syntax like everything else, or this restriction should be clearly documented (it's currently not mentioned anywhere in api_documentation.txt or elsewhere).

Process description:
Found while refactoring, when we wanted to consolidate ~20 variables into one readable, multi-line dict literal (for clarity and maintainability). The first attempt had inline comments next to individual keys and failed - we assumed comments were the problem. An isolated test showed that even a bare 2-key literal with zero comments, just split across lines, fails identically. The only fix was to rewrite the whole literal as one (very long) line.

Steps to reproduce:
1. Run any script containing:
   var x = {
       "a": 1,
       "b": 2
   }
2. Result: "Line N: Expected property name in object literal."
3. The same content on one line (var x = {"a": 1, "b": 2}) works fine.
