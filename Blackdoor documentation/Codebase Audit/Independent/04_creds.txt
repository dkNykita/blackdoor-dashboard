CODEBASE AUDIT - INDEPENDENT PASS
File: utils/creds.bd (~130 lines, 3 functions)
============================================================

read_credentials(nu)
  Location: near top of file. Evidence: 1 real call site
  (utils/sync.bd's do_sync(), which genuinely needs the full
  credentials list to dedup hosts and build the wordlist).
  Nested calls: nu.throttle() per line, read_local(), string split/
  trim/starts_with.
  Purpose: parses ~/.ssh/credentials into a list of {account, host,
  password} objects. Correctly the ONLY remaining caller of this full-
  parse primitive after the double-pass fix (see is_cracked()/cracked_
  accounts_for() below) - do_sync()'s use is legitimate (needs every
  credential, not one).
  Alternatives: none needed - already minimal for a genuine full-list
  need.

is_cracked(nu, account, host)
  Location: mid-file. Evidence: 0 call sites anywhere in the current

  Purpose: "have I already cracked this specific account@host"

cracked_accounts_for(nu, host)
  Location: near end of file. Evidence: ~2 call sites (dashboard.bd's
  refresh_status(), which is the ONLY thing that calls it, called once
  per refresh).
  Nested calls: nu.throttle() per line, read_local(), string ops - does
  NOT call read_credentials() (see its own fix comment - this was
  changed from a two-pass shape to a single inline pass).
  Purpose: "which accounts have I cracked on this specific host" -
  called once per dashboard refresh to drive the USERS section's
  cracked/not-cracked coloring. This is the single most expensive
  per-refresh call in the whole codebase after the fixes so far (still
  ~72.5s per call on a moderately-sized credentials file), because it
  necessarily scans the WHOLE credentials file every single refresh -
  there's no cheaper way to answer "which of my potentially-many
  cracked accounts belong to THIS host" without either scanning
  everything or maintaining a secondary host-keyed index.
  Alternatives:
    - Cache the parsed credentials list across refreshes within one
      script run (menu.bd's dispatch loop calls refresh_status()
      repeatedly without re-importing) - credentials only change when a
      NEW crack happens (do_crack()/do_escalate() append to the file),
      so a cache invalidated only on a fresh crack would avoid re-
      scanning the whole file on every refresh that follows a crack-free
      action (viewing the dashboard, switching targets, etc.). This is a
      genuinely promising, not-yet-tried alternative - no module-level
      caching mechanism has been confirmed reliable in this codebase
      (field_notes.txt's own module-top-level-var caution), so it would
      need to live in menu.bd's own `state` dict instead (state.
      cracked_accounts_cache, invalidated in do_crack()/do_escalate()).
    - Maintain a secondary ~/.ssh/credentials_by_host.txt index
      (host -> account list) written alongside the main file on every
      crack: would turn this into a targeted single-host lookup like
      find_entry_by_host(), at the cost of a second file to keep in
      sync. More invasive than the caching option above but scales
      better if credentials.txt keeps growing across many sessions.
