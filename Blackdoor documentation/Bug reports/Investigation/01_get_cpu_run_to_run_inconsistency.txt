Tags: script

Current behavior:
Running the exact same script logic against the exact same data, back to back in the same session, crashes with "[SYSTEM] CPU overloaded" at wildly different points - not a simple two-way split. 5 consecutive runs of one fixed scenario (decoding a host_intel.txt entry with real, non-empty field data) crashed at: +40.7s, +111.0s, +40.3s, +65.5s, +64.3s.
